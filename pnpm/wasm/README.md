# WebContainer runtime

This runtime executes the pnpm v12 CLI as threaded WebAssembly inside StackBlitz
WebContainers. It is published as the `@pnpm/wasm` npm package, separately from
the native `pnpm` package.
Implementation and validation are tracked in
[pnpm/tasks#63](https://github.com/pnpm/tasks/issues/63).

Native pnpm does not load this package. Native implementations remain selected
at compile time.

## Build and test

From the repository root, with workspace dependencies installed:

```sh
rustup toolchain install nightly-2026-08-27 --profile minimal --target wasm32-wasip1-threads
export WASI_SDK_PATH=/path/to/wasi-sdk-34.0
export WABT_PATH=/path/to/wabt-1.0.42
pnpm build:pnpm:wasm
pnpm pack:pnpm:wasm
node pnpm/wasm/stage.mjs
pnpm build:wasm-runtime-probe
pnpm --filter @pnpm-private/wasm-runtime test
node pnpm/tasks/ecosystem-e2e/webcontainer/run.mjs --wasm-runtime target/wasm-runtime-probe/wasm32-wasip1-threads/debug/pnpm-wasm-runtime-probe.wasm
```

`stage.mjs` writes the `@pnpm/wasm` package to `pnpm/npm/wasm`, which the
release jobs publish. `pack.mjs` packs the same package as `target/pnpm-wasm.tgz`.

The full build uses the pinned nightly because `cap-primitives` requires unstable
WASI filesystem APIs. Native builds retain the repository's stable toolchain.
Download and extract [WASI SDK 34](https://github.com/WebAssembly/wasi-sdk/releases/tag/wasi-sdk-34)
before setting `WASI_SDK_PATH`; the build checks its version and does not download
a compiler. The SDK also builds bundled SQLite with threading enabled.
Extract [WABT 1.0.42](https://github.com/WebAssembly/wabt/releases/tag/1.0.42)
and set `WABT_PATH` to its directory containing `bin`. The build uses its validated
WebAssembly text roundtrip to replace atomic waits with cancellable host imports.
The runtime tests also use this toolchain.

The browser test needs the Chromium installation described in the
[ecosystem test guide](https://github.com/pnpm/pnpm/blob/main/pnpm/tasks/ecosystem-e2e/README.md#webcontainers).
The Node tests require the freshly built probe; missing artifacts are errors.

## Execution model

The Node supervisor owns one WASI descriptor table, the filesystem permission
adapter, network requests and child processes. Rust runs in workers sharing
one WebAssembly memory. All workers use the supervisor's descriptor table,
including when Tokio moves an open file between threads.

The build exports `malloc`, `free`, `__tls_base` and `__wasm_init_tls` for the
thread loader. The supervisor performs shared memory initialization; the main
worker initializes its thread-local storage before calling `_start`.

The `pnpm_atomic` imports provide cancellable atomic waits. WebContainer workers
cannot terminate while parked in a WebAssembly atomic wait. The build rewrites
only wait instructions; loads, stores, notifications and other atomics remain
WebAssembly instructions. Host waits preserve guest deadlines and use bounded
blocking intervals to observe cancellation without a lost wakeup.

The `pnpm_host` imports start asynchronous operations and transfer responses.
One Rust completion thread wakes pending futures. The supervisor retains result
buffers until Rust reads or cancels them; it never retains pointers into guest
memory. Each JSON request or response is limited to 1 MiB. Stream reads transfer
at most 64 KiB of data at a time. HTTP uploads use a separate bounded stream,
so package bodies can exceed the control-message limit. Dropping a request cancels it, and closing the
runtime aborts outstanding operations before terminating the workers.

The `pnpm_fs` imports supply operations WASI lacks: atomic creation with an
explicit mode, descriptor-bound permission changes, and private lock
directories. They use the same descriptor mapping as ordinary WASI calls.

The runtime runs trusted pnpm code with the authority of its Node host. It
preopens the host root; it is not a sandbox for arbitrary WASM modules. Inside
WebContainers this is the container's virtual filesystem.

## Current boundaries

WebContainer's bundled npm applies package replacements through a private host
integration. The standalone pnpm distribution does not depend on that API.
Projects using native tools must select compatible WebAssembly packages through
pnpm's existing overrides. For example, in `pnpm-workspace.yaml`:

```yaml
overrides:
  esbuild: npm:esbuild-wasm@^0.27.0
  rollup: npm:@rollup/wasm-node@^4.43.1
```

Match the replacement versions to the project's dependencies and commit the
lockfile generated by `pnpm install`. This uses the normal resolver and integrity
checks without implicitly substituting package contents.

The browser controls HTTP protocol negotiation and connection pooling. Explicit
custom TLS roots, client certificates, proxies, local addresses and DNS pinning
are rejected by the WASM HTTP adapter. They are not silently ignored. Redirects
remain controlled by the shared Rust network policy.

Process cancellation enumerates descendants with the host's `/bin/ps` and
signals them while the spawned parent is still owned. WebContainers do not
support process-group signals or stable descendant identity handles. If a
parent exits after a graceful signal while a descendant ignores that signal,
the runtime cannot safely target the orphan during later escalation. It does
not retain stale descendant PIDs. Runtime shutdown uses `SIGKILL` for live
owned process trees.

WebContainers do not reliably support numeric file descriptors in child-process
stdio. File redirection therefore uses a pipe bridge, and waiting for the child
also waits for the redirected output to finish writing. A background descendant
that inherits redirected stdout or stderr keeps that wait pending until it closes
the stream, even after the direct child exits. Background children should close
or replace inherited redirected streams.

WASM uses the `v11-wasm` store namespace; native pnpm keeps `v11`. The package
file and index formats match, but live stores are isolated because the locking
protocols differ. An explicit store path ending in `v11` also receives the
`v11-wasm` suffix. Do not symlink the two namespaces together.

SQLite uses a rollback journal and host process leases, because the WASI VFS
cannot provide native advisory locking or WAL. Its [probe](https://github.com/pnpm/pnpm/blob/main/pnpm/tasks/ecosystem-e2e/webcontainer/sqlite-probe/README.md)
and actual Rust store tests cover persistence, contention and crash recovery.

WebContainers cannot restore changed installation metadata through a pinned
directory handle. A failed mutation reports that automatic metadata rollback is
unavailable; it does not write through an unsafe replacement directory. Automatic
provenance signing is also unavailable and returns an explicit error.

Compiling or passing the runtime probe does not establish that all pnpm commands
work in WebContainers. The task tracks CLI integration, command coverage,
packaging and native performance validation separately.
